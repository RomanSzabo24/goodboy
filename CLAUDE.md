# GoodBoy Foundation – Donation Form (GoodRequest FE Assignment)

Full original brief: [docs/input/assignment.md](docs/input/assignment.md). API docs: https://frontend-assignment-api.goodrequest.dev/apidoc/ (OpenAPI spec checked in at [docs/input/openapi.json](docs/input/openapi.json) — treat it as the source of truth for request/response shapes). Figma: https://www.figma.com/design/71F9aOieGNZNowSETLum7t/My-team-Frontend-Assigment-2.0

## Tech Stack & Architecture Rules
- **Framework:** Next.js 16.3.3 (App Router, `src/` directory), TypeScript (strict mode).
- **UI Library:** shadcn/ui (Radix primitives + Tailwind CSS v4).
- **State Management:** 
  - Server state: TanStack Query v5 (`@tanstack/react-query`).
  - Client form state: `react-hook-form` v7 with `@hookform/resolvers` v3+.
  - Shared UI/Multi-step state: React Context, with each wizard step as its own route (URL is the source of truth for current step) and form values held in a single `react-hook-form` instance shared via context.
- **Validation:** Zod v4 schemas.
- **API Base URL:** `https://frontend-assignment-api.goodrequest.dev`
- **Testing:** Vitest + React Testing Library for unit/component tests, Playwright for e2e tests.

## Business & Form Validation Logic
1. **Help Type:**
   - General donation (`GIFT_FOUNDATION`): Shelter choice is optional.
   - Specific shelter (`GIFT_SHELTER`): Shelter choice is **mandatory** (`shelterId` required).
2. **Amount:**
   - Preset options + custom value input (mandatory, positive number).
3. **Personal Details:**
   - `name`: Optional, 2–20 characters if provided.
   - `surname`: Mandatory, 2–30 characters.
   - `email`: Mandatory, valid email format.
   - `phone`: Mandatory, SK (+421) or CZ (+420) format with country flag indicator.
   - `consent`: Mandatory boolean (`true`).

## Code Guidelines
- Use React Server Components by default; add `'use client'` only when using hooks, state, or interactivity.
- Never use the legacy `pages/` router or `any` type in TypeScript.
- Ensure proper accessibility (`aria-label`, correct `htmlFor`, keyboard navigation).
- Keep component structure clean under `src/components/` (shadcn primitives generated into `src/components/ui/`), API logic in `src/services/`, and Zod schemas in `src/lib/validations/`.
- Install/manage shadcn components via the `shadcn` CLI (`npx shadcn@latest add <component>`); do not hand-roll components that already exist in shadcn/ui.

## Verification Commands
- Check types and build: `npm run build`
- Run linter: `npm run lint`
- Run unit/component tests: `npm run test`
- Run e2e tests: `npm run test:e2e`

## Feedback Loop
- After every code edit, run the relevant checks before considering the change done: `npm run lint` and `npm run test` at minimum; also run `npm run build` for changes affecting types, routing, or build config, and `npm run test:e2e` for changes affecting user-facing flows.
- Only run the tests relevant to the change (e.g. scope `npm run test` to the touched file/dir when possible) to keep feedback fast, unless the change is broad enough to warrant the full suite.
- If a check fails, fix the underlying issue before moving on or reporting the task as complete — do not skip or disable checks to make them pass.
